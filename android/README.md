# Leaf Control для Android

Приложение — **WebView-оболочка вокруг настоящей PWA**, а не отдельный
упрощённый интерфейс. Дизайн, история, тариф, OTA и инструменты разработчика
берутся из той же страницы, что открывается в браузере, поэтому отличий от PWA
нет.

## Откуда берётся интерфейс

При запуске приложение:

1. Проверяет плату по адресу из «Настройки Android» (`/api/status`, 1,5 с).
2. Если плата доступна — открывает **`http://<плата>/app`**. Это полная PWA с
   локальными функциями: тариф, история поездок/зарядок, OTA, CAN-монитор,
   журнал разработчика.
3. Если платы нет в этой Wi-Fi — открывает публичную PWA
   `https://wargaelanor.github.io/leafapp/` и работает через MQTT.

Кнопка «Плата» в уведомлении всегда открывает плату, «PWA» в настройках —
публичную версию.

## Что добавлено нативно

- **Фоновая служба** — постоянное уведомление, локальный HTTP или MQTT (WSS),
  восстановление после перезагрузки.
- **Уведомления**: зарядка началась/завершена, низкий заряд, поездка
  завершена, плата не в сети. Действия «Плата» и «Настройки».
- **CSV** — экспорт из истории сохраняется в «Загрузки» телефона.
- **Скачивание файлов** — журнал CAN и другие ссылки идут через DownloadManager.
- **OTA** — выбор файла прошивки через системный файловый диалог.
- **Настройки Android** — пункт в PWA «Ещё», оформлен как остальные строки.
  Там адрес платы, порт, фоновая служба и разрешение работы в фоне.
- **Синхронизация MQTT** — настройки из PWA (`localStorage 'leafcfg'`)
  автоматически передаются фоновой службе.

## Установка

1. Возьмите `dist/LeafControl-1.1-debug.apk`.
2. Разрешите установку из неизвестных источников.
3. При первом запуске разрешите уведомления.
4. Откройте «Ещё → Настройки Android», укажите IP платы (например
   `192.168.1.73` или `192.168.4.1`) и включите фоновый мониторинг.
5. Там же — «Разрешить работу в фоне», чтобы система не убивала службу.

## Настройка

- **Адрес платы** — IP в домашней сети (`192.168.1.73`) или `192.168.4.1` в
  точке доступа платы. `leaf.local` на Android резолвится не всегда.
- **MQTT** — как в PWA: сервер, порт, пользователь, пароль, Vehicle ID.
  Настраивается в самой PWA; приложение подхватывает эти значения.
- **Режим** — «Авто»: сначала локальная плата, затем MQTT.

Приложение не использует FCM и сторонние серверы: уведомления приходят по
MQTT или локальному HTTP, пока работает foreground-служба.

## Сборка

```powershell
$env:ANDROID_HOME="C:\Android\Sdk"
& "C:\Gradle\gradle-8.9\bin\gradle.bat" -p android assembleDebug
```

APK: `android/app/build/outputs/apk/debug/app-debug.apk`.

## Ограничения

- MQTT-брокер должен отдавать WebSocket; приложение пробует путь `/` и `/mqtt`.
- В MQTT-режиме история пишется по телеметрии (одометр, мощность), поэтому
  короткие перемещения менее точны, чем история на самой плате.
- Debug-сборка не подписана для Google Play; для личного использования этого
  достаточно.
