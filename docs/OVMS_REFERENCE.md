# OVMS Nissan Leaf ZE1: команды и разбор CAN

Источник: `vehicle/OVMS.V3/components/vehicle_nissanleaf/src/vehicle_nissanleaf.cpp`
(номера строк указаны по этой копии). Документ фиксирует, что именно делает
OVMS, чтобы наша прошивка могла воспроизвести поведение или осознанно от него
отклониться.

## 1. Шины

| Шина | Назначение | Примечание |
| --- | --- | --- |
| CAN1 | EV-CAN | LBC, VCM, инвертор, PDM. OVMS делает здесь MITM для остановки зарядки |
| CAN2 | CAR-CAN (IT-CAN) | BCM, приборка, замки, климат. На ZE1 OBD-II за gateway |

Обе шины 500 кбит/с. `xnl.ze1` включает только RX-фильтр CAN2 и список
опросов; формат передаваемых кадров от него не зависит.

## 2. Команды

Все команды ZE1 (modelyear ≥ 2016) идут на CAN2 кадром `0x56E`, DLC 4,
**24 повтора по 100 мс** (2.4 с). Перед командой всегда wake:

```text
0x68C  DLC 1  00                (1 раз)
пауза 50 мс
0x56E  DLC 4  46 08 00 00       (1 раз)
```

| Команда | Payload `0x56E` | Повторы | Дополнительно |
| --- | --- | --- | --- |
| Lock | `60 80 00 00` | 24 × 100 мс | досрочно прекращается, когда `v.e.locked = true` (CAN2 `0x60D` b2 bit4) |
| Unlock | `11 00 00 00` | 24 × 100 мс | досрочно, когда `locked = false` |
| Climate ON | `4E 08 12 00` | 24 × 100 мс | через 1 с после старта один кадр `46 08 32 00` (auto-disable timer) |
| Climate OFF | `56 00 01 00` | 24 × 100 мс | — |
| Charge start | `66 08 12 00` | 24 × 100 мс | — |
| Charge stop | — | — | только MITM `0x1DB` на CAN1, см. ниже |

Прочие payload из enum `RemoteCommand`: `86 00 0A 00` (OEM keepalive),
`8E 00 0A 00`, `A6 00 00 00`, `96 00 00 00` — в OVMS не используются как
самостоятельные команды.

### Остановка зарядки (MITM `0x1DB`)

Отдельного `0x56E` payload для ZE1 нет. OVMS перехватывает кадр LBC `0x1DB`
на **EV-CAN** и подменяет его:

```text
new1db[1] = (b1 & 0xE0) | 0x02      // Charging Mode Stop Request
new1db[6] = (b6 + 1) % 4            // PRUN-счётчик
new1db[7] = leafcrc(7, new1db)      // CRC-8, полином 0x85, первые 7 байт
```

Армирование: `m_MITM = 10` (≈9 подмен подряд, ~90 мс) либо снятие по
таймауту 1 с; повторная команда взводит снова.

**Следствие для нашей платы:** Port A объявлен строго listen-only, поэтому
этот механизм физически недоступен: подменять кадр, который видят LBC и
VCM, можно только передавая в EV-CAN. Charge stop без TX на EV-CAN
невозможен — это ограничение архитектуры, а не недоделка.

## 3. Разбор данных: EV-CAN (CAN1)

| ID | Поле | Разбор |
| --- | --- | --- |
| `0x1DB` | ток ВВБ | `d[0]<<3 \| d[1]>>5`, 11 бит, 2's comp, /2 A, знак инвертирован (разряд > 0) |
| `0x1DB` | напряжение ВВБ | `d[2]<<2 \| d[3]>>6`, 10 бит, /2 В |
| `0x1DB` | мощность | `V*I/1000` кВт |
| `0x1DC` | лимиты | разряд `d[0]<<2\|d[1]>>6` /4; рекуперация `(d[1]&0x3F)<<2\|d[2]>>4` /4; заряд `(d[2]&0x0F)<<6\|d[3]>>2` /10 |
| `0x1DA` | момент/обороты | момент `(d[2]&7)<<8\|d[3]` /2 со знаком; обороты `d[4]<<8\|d[5]` /2 со знаком |
| `0x284` | скорость | `d[4]<<8\|d[5]`, /98.0 |
| `0x55A` | мотор/инвертор | `d[1]`, `d[2]` — °F → °C |
| `0x55B` | SOC номинальный | `d[0]<<2\|d[1]>>6`, 10 бит, /10 %, `0x3FF` = нет данных |
| `0x59E` | SOC приборный (ZE1) | `d[7]` /2 % |
| `0x5BC` | GIDS | `d[0]<<2\|(d[1]&0xC0)>>6`, 10 бит; `0x3FF` = нет данных |
| `0x5BC` | SOH | `(d[4]>>1)&0xF7` — только НЕ-ZE1 |
| `0x5BC` | причина лимита заряда | `d[5]>>5` |
| `0x5C0` | температура ВВБ | при `d[0]>>6 == 1`: `d[2]/2 - 40` °C |
| `0x54A` | уставка климата | `d[4]/2` °C |
| `0x54B` | вентилятор/климат | `(d[4]&0x38)>>3`; режимы в `d[1]` (зависит от года) |
| `0x54C` | за бортом | `d[6]/2 - 40` °C |
| `0x54F` | салон (ZE1) | `d[0]/2 - 40` °C |

## 4. Разбор данных: CAR-CAN (CAN2)

| ID | Поле | Разбор |
| --- | --- | --- |
| `0x355` | единицы одометра | `(d[6]>>5)&1`, 1 = мили |
| `0x385` | давление в шинах | `d[2..5]` /4 PSI |
| `0x421` | селектор | `(d[0]>>3)&7`: 2 = R, 4/7 = D |
| `0x5A9` | запас хода приборный | `d[1]<<4\|d[2]>>4`, /5 км (на ZE1 врёт) |
| `0x5B9` | деления заряда | `(d[1]&0xF8)>>3` |
| `0x5C5` | одометр | `d[1]<<16\|d[2]<<8\|d[3]` км |
| `0x60D` | двери/свет/замок | `d[0]` b7..b3 двери; `d[2]` b4 = lock |

## 5. Диагностика BMS (ISO-TP)

OVMS опрашивает на **CAN1** (`0x79B` → `0x7BB`), у нас — те же запросы на
CAR-CAN, gateway их маршрутизирует.

| Группа | Ответ | Разбор |
| --- | --- | --- |
| `21 01` | 51 байт (ZE1) | SOC `[31..33]/10000`, Ah `[35..37]/10000`, Hx `[28..29]/102.4` |
| `21 02` | 196 байт | 96 ячеек по 2 байта BE, мВ; `>=5000` — пропуск |
| `21 04` | 14 или 29 байт | 4 блока по 3 байта: `-0.102*(thermistor-710)` °C |
| `21 06` | 24 байта | 96 бит шунтов (только при зарядке) |
| `21 61` | 329 байт | SOH `[2..3]/100` |

VIN: запрос `0x797  02 21 81` → ответ `0x79A  61 81` + 17 ASCII символов
(в OVMS дополнительно `00 00`). 12 В ток: `0x797 22 11 83`, 2 байта BE
signed /256 A.

## 6. Чем наша реализация отличается

| Тема | OVMS | У нас | Причина |
| --- | --- | --- | --- |
| Charge stop | MITM `0x1DB` на EV-CAN | недоступно | Port A строго listen-only |
| Климат ON | `4E 08 12 00` ×24 + `46 08 32 00` | OEM-последовательность с `0x12/0x32` | проверено физически на этой машине |
| Lock/Unlock | `60 80`/`11 00` ×24 | те же payload, свой ритм | приводы щёлкали при 24 повторах |
| BMS опрос | на EV-CAN | на CAR-CAN через gateway | Port A без TX |
| SOC | `0x55B` + BMS `0x01` | `0x55B`, теперь и BMS `0x01` | — |
