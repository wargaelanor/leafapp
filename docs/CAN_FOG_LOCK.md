# Разбор: туманки и кнопка «закрыть» с брелка (CAN-логи 09.11.2026)

## Методика
Три лога формата `time bus dir id len data` (A=EV-CAN, B=CAR-CAN):
`туманки 10 раз вкл выкл.txt`, `стоп педаль 10 раз.txt` (репер),
`кнопка закрыть с ключа8-10.txt`. Для каждого (bus,id) считали число
переключений байтов; rolling-счётчики/CRC (≥80 % фреймов с изменением)
отброшены; кандидаты проверены кросс-диффом значений fog/brake/fob.

## 1. Туманка — состояние в 0x60D byte2 бит 0x04

Каркас — штатный CAN-статус BCM (двери/замки/свет, ~1 Гц + событийный):

```
туманки ВЫКЛ:  B < 0x60D 8 06 06 18 00 00 00 00 00
туманки ВКЛ :  B < 0x60D 8 06 06 1C 00 00 00 00 00
                              ^  ^  ^
                              |  |  + byte2: 0x1C = туманка ON (+бит 0x04)
                              |  + byte1=0x06: состояние READY (биты mask 0x06)
                              + byte0=0x06: ближний свет включён (mask 0x02)
```

Раскладка byte2 (`d[2]`):
- `0x10` — центральный замок **закрыт** (уже парсится прошивкой, `locked_field`)
- `0x08` — константа во всех трёх логах (габариты/реле света)
- **`0x04` — ТУМАНКИ** — значение 0x1C встречается ТОЛЬКО в туманочном логе
  (7 фреймов, 0.96–11.37 с); в brake-логе byte2 ≡ 0x18, в fob-логе ≡ 0x18.

Почему только 7 из ~20: при быстрых переключениях ~1-секундный опрос
0x60D сэмплирует квадратную волну ~1.4 с и алиасит — часть «вкл» не
попадает в выборку; в brake- и fob-логах бит 0x04 не дёргается вообще.

**ВАЖНО:** команда «включить туманку» по CAN в логах ОТСУТСТВУЕТ —
подрулевой переключатель туманок висит на BCM линией/LIN, не шиной.
0x60D — только **статус**. Управляемо снаружи: вспышка света через
0x56E (уже в прошивке: `lights_data 46 09 12 10`). Для реального
управления туманками нужен только приём статуса + (при желании)
релейное вмешательство в обвод.

## 2. Кнопка «закрыть» с брелка

### Событие нажатия (каждый раз) — импульс 0x60D byte1 = 0x60
```
B < 0x60D 8 00 60 18 00 00 00 00 00   ← подтверждение (вспышка поворотников)
```
Паульсы ровно в окнах нажатий: 2.123, 2.223, 3.142, 3.708(×2), 4.459,
5.228 — 7 импульсов (машина уже заперта, BCM подтверждает миганием).
byte1=0x60 **никогда** не появляется в fog/brake-логах (там byte1=0x06).
Обычное состояние при парковке: `00 00 18` (byte1=0x00, carState=off).

### Первый «холодный» клик будит машину — редкая тройка (уникальна fob-логу):
```
B < 0x682 1 00          ← wake-запрос BCM (RF приём)
B < 0x601 2 83 C0       ← car awake (уже в прошивке как car_awake_readout)
B < 0x602 1 00          ← подтверждение
+ через 0.2 с UDS-опрос VIN (0x183EF000/0x183F0000 — не связаны)
```

### Итоговая формула детекции для платы
```
fob lock press = (id==0x60D && bus B && d[1]==0x60)
              || (id==0x682 && d[0]==0x00 && bus woken)
locked state   = (0x60D d[2] & 0x10)
fog state      = (0x60D d[2] & 0x04)
```

## Кросс-подтверждение: Leaf2018-CAN.pdf (Meter, стр. 12–13)
В `D:\YandexDisk\ZE1-036135\Leaf2018-CAN.pdf` (текст извлечён в
`leafapp/docs/Leaf2018-CAN.txt`) туманки определены через UDS-опрос Meterа:
`0x745 [02 21 09]` → ответ `0x765 [10 10 61 09 AA BB CC XX]`,
где data[4]=Wiper, data[5]=Light1, data[6]=Light2; «Anti fog lights = 1»
например при Light1=0x02 и Light2 ∈ {0x08, 0x28, 0xc8, 0xe8}.
Это независимо подтверждает наше обнаружение: туманка кодируется
младшим битом маски 0x08 (бит 0x04) в байте состояния света —
в вещаемом BCM-статусе `0x60D` это ровно `d[2] & 0x04` (18→1C).

## Побочный вывод (отброшенные кандидаты)
- 0x54A/0x54F/0x55B/0x5BC/0x5A9/0x02A/0x351/0x358/0x35D/0x4F2/0x50A/0x510/
  0x515/0x5C5/0x60D и пр. burst-кластеры каждые ~0.9–1.1 с — фоновый
  опрос BCM с rolling-счётчиками, идентичен во всех логах (в brake-логе
  byte2 всегда 0x18).
- A/0x1DB, A/0x6B0, B/0x292 — EV-CAN ток/SOC и security-счётчики.
