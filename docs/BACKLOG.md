# План работ: что делаем и в каком порядке

Объединённый список из двух наборов предложений. Статусы: `[ ]` — в очереди, `[~]` — в работе, `[x]` — сделано.

## Партия 0 — история на плате

- [x] **Запись поездок и зарядок на плате.** JSONL в FAT: `/trips.jsonl` (~1 МБ, ~6000 записей) и `/charges.jsonl` (~256 КБ, ~1600). Старые записи вытесняются половиной файла. Приложение только читает (`GET /api/trips`, `/api/charges`) и очищает.
- [x] **Дневной и ночной тариф.** Окно по умолчанию 00:00–07:00, энергия распределяется по времени, стоимость в рублях в карточках.
- [x] **Скрытая перезагрузка платы.** Настройки → Обслуживание, удержание 3 секунды.

## Партия 1 — надёжность и диагностика

- [x] **1. Само-восстановление Wi-Fi.** После 3 неудачных циклов «перезапуск радио» — полная перезагрузка платы; причина пишется в статус.
- [x] **3. Сторож памяти.** Свободная память ниже порога → мягкая перезагрузка с записью причины.
- [x] **4. Страница «Диагностика».** Одним экраном: прошивка, uptime, причина перезагрузки, память, RSSI, ошибки CAN, возраст данных BMS, часы платы.
- [x] **5. VIN по OBD-II `09 02`.** Кнопка в диагностике; при ответе VCM — VIN в приложении.
- [x] **10. Лёгкая страница: статус и основные цифры.** Блок диагностики убран по просьбе.

## Правила, которые не меняем

- Port A (EV-CAN) — только приём, команды только через Port B.
- Неизвестные кадры не отправляются: только сохранённые пользователем, после явного разрешения на 10 минут.
- Устаревшие данные показываются как «—», а не как живые.
- Секреты не попадают в Git.
