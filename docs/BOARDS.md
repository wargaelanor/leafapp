# Две платы: T-2CAN и TTGO T-Call 1.4

Принцип: **один код, два профиля сборки**. Не две разные прошивки, которые
расходятся через месяц, а один исходник и два набора пинов/флагов.

Git-ветки `release-t2can` и `release-tcall` — только для снимков релизов.
Разработка идёт в `sim800`/`main`, отличается только профиль сборки.

## Профиль 1: LilyGO T-2CAN + внешний SIM800 (текущая плата)

| Что | Значение |
| --- | --- |
| MCU | ESP32-S3, 16 МБ flash, 8 МБ PSRAM |
| PSRAM | **выключена**: GPIO33–37 заняты SIM800 (35/37) |
| CAN B (CAR-CAN) | встроенный TWAI, TX=GPIO7, RX=GPIO6 |
| CAN A (EV-CAN) | MCP2515 по SPI: SCK=12, MISO=13, MOSI=11, CS=10, RST=9, INT=8; **только приём** |
| SIM800 | RX=GPIO35, TX=GPIO38, RI=GPIO37 |
| История | FFat 9 МБ: ~6000 поездок / ~1600 зарядок |
| Сборка | `FlashSize=16M`, `PartitionScheme=app3M_fat9M_16MB`, `PSRAM=disabled` |

Это состояние прошивки `.98`, которая сейчас на плате. Она рабочая, её не
трогаем без необходимости.

## Профиль 2: TTGO T-Call 1.4 + два MCP2515

| Что | Значение |
| --- | --- |
| MCU | ESP32-WROVER-IB, 4 МБ flash, 8 МБ PSRAM (в этом экземпляре PSRAM определилась как 0) |
| CAN 1 (CAR-CAN) | MCP2515 #1, normal mode: CS=GPIO25 |
| CAN 2 (EV-CAN) | MCP2515 #2, listen-only: CS=GPIO14 |
| Общая SPI-шина | SCK=GPIO18, MISO=GPIO34, MOSI=GPIO19, 4 МГц |
| MCP2515 #3 | задел на будущее: CS=GPIO15, в прошивке линия удерживается в HIGH, модуль не подключён |
| INT / RST | не подключены, драйвер опрашивает регистры; RST — на 3,3 В |
| SIM800 | встроенный, **включён**: TX=GPIO27, RX=GPIO26, RI=GPIO33, PWRKEY=GPIO4, POWER_ON=GPIO23, RST=GPIO5, DTR=GPIO32 |
| PMU | IP5306, I2C SDA=21, SCL=22 (используется только если модем включён) |
| История | SPIFFS 128 КБ: ~96 КБ поездок / ~24 КБ зарядок |
| Сборка | `FlashSize=4M`, `PartitionScheme=min_spiffs`, `PSRAM=enabled`, `-DLEAF_BOARD_TCALL=1` |
| Размер | ~1,73 МБ из 1,97 МБ (87%) |

### Ограничения T-Call

1. **GPIO5, GPIO21 и GPIO23 заняты намертво** — это SIM800 RESET, PMU SDA и
   SIM800 POWER_ON. Их нельзя использовать под SPI: первые же импульсы
   сбросят модем или отключат питание PMU. ESP32 не имеет права менять эту
   разводку, поэтому SPI вынесен на свободные 18/34/19/25/14/15.
2. **4 МБ flash.** `min_spiffs` даёт 1,9 МБ под приложение и OTA; занято ~87%.
   История на SPIFFS маленькая (~600–800 записей).
3. **Логика 3,3 В.** ESP32 не переносит 5 В на входе. Питайте модули MCP2515
   от 3,3 В (MCP2515 работает от 2,7–5,5 В) либо ставьте level shifter на
   MISO/MOSI/SCK/CS. Если модуль запитан от 5 В и без сдвига уровней, его
   MISO выдаёт 5 В — это опасно для ESP32.
4. **Кварц MCP2515.** По умолчанию прошивка ждёт 16 МГц — как на модуле,
   который уже проверялся на этой машине. Если CAR-CAN молчит, а трансивер
   подключён, поменяйте `BOARD_CAR_MCP_CLOCK` на `MCP_8MHZ` в `boardConfig.h`
   и пересоберите: дешёвые синие модули часто идут с 8 МГц.
5. **Терминация.** На каждой шине 120 Ом на концах; в модулях MCP2515 часто
   уже стоит резистор — при двух модулях на одной шине оставляйте один.
6. **GPIO15 — strapping.** Для третьего модуля подтяните его CS к 3,3 В
   (10 кОм), иначе возможны проблемы при старте. Сейчас модуль не подключён,
   прошивка просто держит линию в HIGH.
7. **GPIO13 — светодиод платы.** Мы его не используем, чтобы SPI не мигал
   индикатором. **GPIO35 — делитель напряжения АКБ**, для CAN не годится.
   GPIO34 — input-only, используется только для MISO.
8. **PSRAM.** В проверенном экземпляре `PSRAM: 0 bytes`; на работу не влияет,
   heap ~259 КБ.
9. **Веб-приложение без слоёв и шрифтов.** Для T-Call `mkwebapp.ps1` не
   встраивает `car-*.png` и шрифты Nissan (экономия ~260 КБ).
10. **CAN-журнал.** На T-Call нет FAT-раздела под `canlog.bin`; журнал CAN
   остаётся функцией T-2CAN. История поездок на T-Call живёт в SPIFFS.

## Сборка

```powershell
# T-2CAN
tools\build.ps1 -Board t2can

# T-Call
tools\build.ps1 -Board tcall
```

Скрипт выставляет FQBN и `-DLEAF_BOARD_TCALL` для второго профиля. Оба
бинарника кладутся в отдельные папки, чтобы не перепутать при заливке.

## Статус

- Профиль T-2CAN: на плате `FW-2026.11.08.109-CMD`, собран `.116-CMD`.
  Тариф хранится в NVS, история очищена от фантомных 5–15-секундных «зарядок».
  В `.114` страница настроек прокручивается внутри `.screens` (pull-to-refresh
  отключён), добавлен поиск Wi-Fi сетей и снижена мощность Wi-Fi до 11 dBm
  против просадок питания. Wi-Fi iWiFi на плате пока не поднялся.
  В `.115` время платы хранится в NVS и принимается от приложения по
  `/api/time`, поэтому история пишется и в режиме точки доступа без NTP.
- Профиль T-Call: на плате `FW-2026.11.08.113-TCALL`, собран `.116-TCALL`.
  Обе шины — на MCP2515: общая SPI-шина SCK=18/MISO=34/MOSI=19,
  #1 CAR-CAN CS=25 (normal mode), #2 EV-CAN CS=14 (listen-only),
  #3 зарезервирован CS=15. GPIO5/21/23 заняты SIM800/PMU и в SPI не входят.
  SIM800 остаётся на 26/27/32/33/4/23/5 и включается в настройках.
  На старом модуле MCP2515 (CS13) чип не отвечал (`CANSTAT=0x00`) —
  проверяются питание/пайка и новая разводка.
  В `.115` SIM800 отдаёт сетевое время через `AT+CCLK?`.
- На проверенной T-Call `PSRAM: 0 bytes` — либо модуль без PSRAM, либо
  опция не подхватилась. На работу это не влияет.
- Оба профиля собираются из одного исходника; отличие — только
  `-DLEAF_BOARD_TCALL=1` и FQBN.
