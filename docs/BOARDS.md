# Две платы: T-2CAN и TTGO T-Call 1.4

Принцип: **один код, два профиля сборки**. Не две разные прошивки, которые
расходятся через месяц, а один исходник и два набора пинов/флагов.

Git-ветки `release-t2can` и `release-tcall` — только для снимков релизов.
Разработка идёт в `sim800`/`main`, отличается только профиль сборки.

## Профиль 1: LilyGO T-2CAN + внешний SIM800 (текущая плата)

| Что | Значение |
| --- | --- |
| MCU | ESP32-S3, 16 МБ flash, 8 МБ PSRAM |
| PSRAM | **выключена**: GPIO33–37 заняты SIM800 (35/37) |
| CAN B (CAR-CAN) | встроенный TWAI, TX=GPIO7, RX=GPIO6 |
| CAN A (EV-CAN) | MCP2515 по SPI: SCK=12, MISO=13, MOSI=11, CS=10, RST=9, INT=8; **только приём** |
| SIM800 | RX=GPIO35, TX=GPIO38, RI=GPIO37 |
| История | FFat 9 МБ: ~6000 поездок / ~1600 зарядок |
| Сборка | `FlashSize=16M`, `PartitionScheme=app3M_fat9M_16MB`, `PSRAM=disabled` |

Это состояние прошивки `.98`, которая сейчас на плате. Она рабочая, её не
трогаем без необходимости.

## Профиль 2: TTGO T-Call 1.4 + MCP2515/MCP2551

| Что | Значение |
| --- | --- |
| MCU | ESP32-WROVER-IB, 4 МБ flash, 8 МБ PSRAM (в этом экземпляре PSRAM определилась как 0) |
| CAN 1 (CAR-CAN) | встроенный TWAI + MCP2551: TX=GPIO32, RX=GPIO33 |
| CAN 2 (EV-CAN) | MCP2515 по SPI: CS=12, SO/MISO=14, SI/MOSI=27, SCK=26, INT=25, RST — на 3,3 В; MCP2551: CRX=33, CTX=32 |
| SIM800 | **отключён**: GPIO26/27/32/33 заняты CAN; профиль T-Call собирается с `BOARD_HAS_MODEM 0` |
| PMU | IP5306, I2C SDA=21, SCL=22 (используется только если модем включён) |
| История | SPIFFS 128 КБ: ~96 КБ поездок / ~24 КБ зарядок |
| Сборка | `FlashSize=4M`, `PartitionScheme=min_spiffs`, `PSRAM=enabled`, `-DLEAF_BOARD_TCALL=1` |
| Размер | ~1,71 МБ из 1,88 МБ (87%) |

### Ограничения T-Call

1. **Конфликт с SIM800.** Пины CAN 26/27/32/33 — это UART/DTR/RI встроенного
   SIM800. В профиле T-Call модем отключён, его rail гасится при старте.
   Если нужен SIM800, CAN-пины придётся перенести или убрать модем.
2. **4 МБ flash.** `min_spiffs` даёт 1,9 МБ под приложение и OTA; занято ~87%.
   История на SPIFFS маленькая (~600–800 записей).
3. **MCP2551 — 5 В.** CRX выдаёт 5 В, а GPIO33 — 3,3 В: нужен делитель
   (10 кОм / 20 кОм) или level shifter. CTX 3,3 В может не дотянуть до VIH
   MCP2551; лучше SN65HVD230/TJA1051T/3.
4. **GPIO12 — strapping MTDI.** CS не должна быть подтянута высоко при
   старте, иначе ESP32 может выбрать 1,8 В flash и не загрузиться. Если после
   пайки MCP2515 плата не стартует — перенесите CS на 13/15/21/22.
5. **PSRAM.** В проверенном экземпляре `PSRAM: 0 bytes`; на работу не влияет,
   heap ~259 КБ.
6. **Веб-приложение без слоёв и шрифтов.** Для T-Call `mkwebapp.ps1` не
   встраивает `car-*.png` и шрифты Nissan (экономия ~260 КБ).
7. **CAN-журнал.** На T-Call нет FAT-раздела под `canlog.bin`; журнал CAN
   остаётся функцией T-2CAN. История поездок на T-Call живёт в SPIFFS.

## Сборка

```powershell
# T-2CAN
tools\build.ps1 -Board t2can

# T-Call
tools\build.ps1 -Board tcall
```

Скрипт выставляет FQBN и `-DLEAF_BOARD_TCALL` для второго профиля. Оба
бинарника кладутся в отдельные папки, чтобы не перепутать при заливке.

## Статус

- Профиль T-2CAN: прошивка `.98` на плате, поведение не менялось.
- Профиль T-Call: собран и залит на COM40 (`FW-2026.11.08.99-TCALL`).
  Загрузка подтверждена: AP `LeafControl-Setup` на 192.168.4.1, mDNS
  `leaf.local`, TWAI-драйвер установлен, история в SPIFFS смонтирована.
  MCP2515 пока не распаян — `EV-CAN: MCP2515 not responding` это ожидаемо.
- На проверенной T-Call `PSRAM: 0 bytes` — либо модуль без PSRAM, либо
  опция не подхватилась. На работу это не влияет; при необходимости
  проверим отдельным скетчем.
- Оба профиля собираются из одного исходника; отличие — только
  `-DLEAF_BOARD_TCALL=1` и FQBN.
