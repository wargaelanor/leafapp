# Leaf Control — план проекта

## Цель

Система мониторинга и удалённого управления Nissan Leaf (поколение ZE1):
плата на ESP32-S3 подключается к автомобилю по CAN, публикует состояние и
принимает команды через MQTT, предоставляет локальный веб-интерфейс.
Клиенты — веб-приложение (PWA) и (в плане) нативное Android-приложение.

## Состав репозитория

| Путь          | Назначение                                                        |
|---------------|-------------------------------------------------------------------|
| `index.html`, `sw.js`, `manifest.webmanifest`, `fonts/`, иконки | PWA (публикуются на GitHub Pages) |
| `firmware/LeafControl/` | Arduino-скетч прошивки платы (ESP32-S3, arduino-esp32) |
| `tools/`      | Утилиты сборки (генерация встроенного в прошивку веб-интерфейса)  |
| `docs/`       | План, история изменений, релизы, заметки для ИИ-агентов, журнал   |

## Архитектура

```
Nissan Leaf (CAN) ←> ESP32-S3 плата ←→ Wi-Fi / MQTT брокер
                          │                    │
                   локальный веб-UI      PWA (MQTT-режим)
                          │
                     OTA-обновления
```

- **Прошивка**: чтение шины CAN (ZE1), REST API (`/api/status`, команды
  POST), MQTT-клиент (TLS, Home Assistant discovery), встроенный веб-UI,
  web-OTA, deep sleep с таймерными пробуждениями, опциональный GSM-модем
  (SIM800 / A7670) как резервный канал MQTT при пропадании Wi-Fi,
  serial CLI.
- **PWA**: два режима — локально с платой (REST) и через MQTT-брокер;
  оффлайн (service worker), журналы поездок и зарядок (IndexedDB),
  быстрые команды (двери, свет, климат), поиск машины по GPS модема.
- **Встроенный веб-UI платы**: генерируется из PWA-разметки и
  прошивается внутрь платы (см. `tools/mkwebapp.ps1`), доступен без
  интернета через точку доступа платы.

## Дорожная карта

### Готово
- PWA: интерфейс, MQTT/локальный режимы, оффлайн, quick actions,
  журналы поездок и зарядок, GPS из модема (версии leaf-v1…leaf-v10).
- Прошивка: CAN, MQTT с TLS, веб-настройки с сохранением в NVS,
  serial CLI, встроенный веб-UI, web-OTA, deep sleep, модем,
  чекбоксы настроек рендерятся корректно (фикс 22.10.2026).

### В работе / ближайшее
- Captive portal для точки доступа платы (DNS-редирект на веб-UI) —
  реализовывался, в текущий снапшот не включён; включить отдельной
  заливкой после проверки.
- Диагностика обрывов web-OTA (первый upload обрывался, повтор прошёл).

### План (решение принято)
- **Нативное Android-приложение** (Kotlin) вместо push-инфраструктуры
  для PWA:
  - полностью нативный UI; локальное хранение (SQLite);
  - фоновая подписка на MQTT + локальные уведомления по изменению
    состояния — **без сервера и без FCM**;
  - два режима доставки: **WorkManager с настраиваемым интервалом
    (по умолчанию ~15 мин)** + опционально foreground-сервис для
    частых обновлений (учитывая ограничение ОС: периодический фон —
    не чаще ~1 раза в 15 мин, для чаще нужен foreground/AlarmManager);
  - команды уходят в топик команд платы (см. `mqttInterface.cpp`).

## Ключевые решения

- Пуши не нужны в веб-UI самой платы; для PWA push реализуются только
  в рамках открытой вкладки (браузерное ограничение, особенно iOS).
- Команды — только POST (защита от CSRF через GET).
- Wi-Fi имеет приоритет над GSM-модемом: модем поднимается, когда Wi-Fi
  недоступен >60 с, и выключается при возврате Wi-Fi.
- Deep sleep: счётчик простоя хранится в RTC и НЕ сбрасывается
  активностью UI; после ухода в сон плата просыпается на ~90 с каждые
  N минут (N настраивается, ускоренный/замедленный режим).
